# Product specification

The first milestone provides a local formatted crea gallery. It reads `Crea/` without changing source files and excludes Repost and Misc folders. Metadata comes from filename codes; missing or conflicting metadata appears in import review. Missiles is a single-type branch.

Each derived image is a 1920×1920 JPEG at quality 92. Artwork occupies the top 1920×1680 area. Default placement enlarges the complete source image to fit without cropping; remaining space shows a blurred, darkened cover copy of the source. A per-asset editor can instead crop to fill using horizontal and vertical focal positions. The bottom 240 px bar uses a saved creator color, a type symbol and large three-letter type code on the left, and a large `N BP` count at the far right when present. A creator with no saved color prompts for one before its images are formatted.

The desktop gallery uses five columns, horizontal branch navigation, vertically scrolling collapsible type sections, search, creator filtering, and asset details. Smaller screens use fewer columns. The gallery shows formatted image thumbnails only, with no metadata strip beneath them; the information button opens details. The dark green and coffee-brown interface places an app menu at the far left of the header and the white bird mark beside Clan Hub. The app menu contains Settings, Review, Scan collection, Used Crea, and persistent zoom controls from 70% to 150%. Interface text uses a serif font. The Settings page manages saved creator bar colors and visibility toggles. Disabled creators' crea are hidden from gallery and Used Crea and omitted from visible counts, while stored assets, usage state, and existing packages remain intact. Re-enabling a creator reveals their crea again. The bird also supplies favicon and PWA icons on a rounded dark green tile. Direct Discord drag remains experimental; the mobile companion uses the shared desktop backend.

Clicking a gallery card adds that crea directly to Hot Staging; clicking an already staged card removes it from Hot. A separate control opens asset details. Hot Staging sits below search and above branch navigation, showing up to ten centered images on one row. Its compact rounded panel sticks to the top of the viewport as the gallery scrolls, without covering the search controls at the top of the page. When Hot has ten crea, gallery cards outside Hot become gray and cannot be added; their detail controls remain available. An eleventh addition is also rejected by the backend without changing the package. The wrapped submission editor occupies about two card widths and one card height beside the images, with a copy button inside it. Send staged crea sits above Move to Reserve beside the editor. Each package holds one submission text. The Send outbox copies all formatted Hot JPEGs together as native file references through the desktop FileTransfer portal; submission text has a separate copy action. Copying leaves staging intact. After a successful package clipboard request, the icon changes to Confirm sent. Only confirmation marks assets used, removes them from the available gallery, and clears Hot.

Reserve Staging is a compact rounded panel pinned near the bottom of the viewport with layered-image deck tiles: ten columns per desktop row, vertical scrolling for additional rows, and fewer columns on narrow screens. Both staging panels have accessible names without visible Hot or Reserve labels; Reserve has no package-count heading. Asset details temporarily compress both panels and use a narrower side panel. Clicking a deck opens an in-app preview of all its crea, submission, and warnings. Activation remains a separate action or drag to Hot.

Confirmed assets are replaced in other Reserve packages with unused assets of the same branch and type, without duplicates within a package. Missing replacements appear as grayed crea cards with an alert badge in Hot Staging and Reserve preview; the Reserve deck also carries a warning. Missing slots must be removed and replaced before confirmation. BP-bearing replacements require explicit package review acknowledgement. Used Crea supports individual, selected, and all-asset restoration. Direct Discord dragging remains experimental.

On the Electron desktop, dragging any Hot crea to Reserve moves the entire package. When Discord is installed as a Flatpak, derived files are exported read-only through the document portal for Discord to access. Dragging a Hot card to Reserve moves the package inside Clan Hub. Native drag preparation rejects missing crea or missing formatted files. An attempted native drag keeps Hot intact; confirm only after the files are posted in Discord. The accepted external drop signal has not yet been verified on KDE Wayland, so the app does not clear Hot automatically. Each confirmed deployment stores a transactional recovery snapshot. Used Crea offers Undo last deployment while staging and usage still match the post-deployment state; later changes disable Undo to avoid overwriting newer work. The desktop window can shrink to 420 px wide; the gallery changes from five columns down to one as available width decreases, while the Hot row scrolls horizontally when necessary.

The Hot folder control opens the persistent app-managed `hot-staging/` folder in Files. Its numbered formatted JPEG copies automatically mirror current Hot membership; removed or confirmed crea disappear from the folder. The folder stays at the same path even when empty, and Dolphin can remain open while its contents update. Copies are separate from the immutable source collection. Opening or dragging from the folder does not change package state.

The mobile companion shows only the gallery, Hot Staging, Reserve Staging, and lightweight search and branch/type/creator filters fixed beneath Reserve. It does not expose Settings, asset information, import review, or the Used Crea collection. Phone staging operations update desktop state and the persistent Dolphin Hot folder. It requires pairing and private Tailscale HTTPS access while the desktop app is open.

Tapping a Hot thumbnail once marks it for removal with dimming and a trash icon; tapping the same thumbnail again removes it. Tapping elsewhere cancels or changes the pending selection. Selected crea are dimmed and outlined in desktop and mobile galleries. The phone gallery has three columns within collapsible type sections, expanded by default. Seven mounted branch panels follow horizontal finger movement and settle on release; each panel retains its own vertical scroll and type-section state. The bottom branch selector controls the same carousel. Search, type, and creator filters stay beneath Reserve. The first tap on mobile Send requests the full Hot package on the Framework clipboard; it does not copy files to the phone. After clipboard success, the same button becomes Confirm sent. Tapping it after posting marks those crea used and clears Hot. A failed clipboard request, disconnection, or Hot package change removes the confirmation state. Confirmation checks the package ID and asset IDs in one backend transaction.

On the phone, a 250 ms hold on any Hot thumbnail starts a drag of the entire Hot package to Reserve. A hold on a layered Reserve deck starts a drag to Hot; activating a Reserve package swaps an occupied Hot package into Reserve. A floating preview shows up to three crea and the package count. Only the valid destination highlights. A canceled drag leaves staging unchanged. A short tap retains Hot's two-tap removal and Reserve's package preview. Disconnection and package changes cancel active gestures. The backend validates the Hot package ID on mobile Reserve moves.

Desktop and mobile gallery cards toggle Hot membership on click or tap. Selected cards remain actionable when Hot is full so they can be deselected; unselected cards remain disabled at the ten-crea limit. The Hot-panel two-tap removal remains separate.
